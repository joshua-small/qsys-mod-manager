# Profiles and grouped operations

Profiles are metadata-only JSON (`.qdsprofile`), schema 1. Each has a stable UUID, display name, Designer version and exact host/common hashes, and a unique set of supported mod IDs with exact assembly versions, package SHA-256 hashes and enabled states. Import validates bounded metadata and creates a new identity without applying it. Packages remain separate `.qdsmod` files.

The profile library lives beside existing settings in `%LOCALAPPDATA%\QDS Mod Manager\profiles.json`. Opening a supported installation captures its existing managed configuration as an initial profile; this does not modify installation files or erase old packages/backups. Unknown files are never included in a profile. A saved profile can be assigned to several installations. Each installation retains its own applied snapshot until explicitly changed. An assigned profile cannot be deleted; switch its installations first.

Registry schema 2 adds the applied profile snapshot and suspension flag to the existing managed mod records. Older schema-1 state remains readable. The next successful operation upgrades it. A previous manager cannot manage schema-2 state; use the new manager's Undo rather than downgrading the application to change mods.

Profile switching, bulk updates and suspension use one journal and one installation lock. Preparation resolves every exact pin from the trusted catalog, verified imported packages or the installation's verified package store. All downloads finish before the preview and any installation write. Missing or incompatible pins reject preparation. Apply checks the preview stamp and rebuilds/verifies the entire change. Existing exact-build, shared-file, reparse-path, external-edit and running-Designer checks remain in effect. File and state changes share the same verified before/after backups. Rollback, interrupted recovery and Undo restore the complete applied snapshot, including suspension. Shared libraries and unrecognized modules are retained.

Suspension removes only managed mod payload/marker files while retaining desired enabled states in the profile. Resume restores only those enabled pins. Individual mod changes are unavailable during suspension; bulk updates can revise pins while leaving managed mods suspended. Successful individual changes revise the applied profile. The UI reconciles committed installation state into the library, including after an interrupted UI handoff or undo. Other installations are never written by this reconciliation.

Catalog schema 1 remains unchanged because 0.5.1 rejects unknown JSON members. Optional `catalog/presentation.json` supplies author, trusted thumbnail/help URLs and per-version release notes. Author values use GitHub usernames; the UI links them to GitHub profiles. Older cached display names fall back to the trusted repository owner. Its failure cannot prevent catalog/package use. Append releases to the index and retain published package assets: replacing old entries would break exact profile pins. Older locally supplied packages remain resolvable through verified cache/import even when never published.

Source acceptance is distinct from Designer acceptance. Tests exercise file operations on disposable fixtures; no DSP/Core behavior or Designer acceptance of new extensions is claimed.
